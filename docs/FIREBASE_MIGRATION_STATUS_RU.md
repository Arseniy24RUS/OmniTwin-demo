# Firebase: статус переноса чата

Checkpoint на 7 сентября 2026 года по подтверждённым операторским проверкам.
Инфраструктура создана, функция `chatApi` ACTIVE, публичный серверный LLM-путь
проверен. Активация и реальная браузерная проверка GitHub Pages ещё выполняются;
полная готовность публичного интерфейса пока не подтверждена.

## Решение владельца о расходах

Владелец явно отказался от отдельного лимита ключа OpenRouter и разрешил
публичное включение без ранее предложенного cap $5. По сообщению владельца,
предоплаченный баланс составляет $8, автопополнение отключено; эти два свойства
не выдаются за независимо проверенные настройки аккаунта. Существующий ключ
сохранён, `limit: null` принят согласно этому решению. Настройки аккаунта,
лимит, автопополнение и сам ключ при включении не менялись. Это не абсолютный
лимит расходов Google Cloud; серверные квоты и ограничения масштабирования
сохранены.

## Не завершено

1. Реальная браузерная Pages→API проверка и подтверждение опубликованного runtime config ещё не завершены. Серверный POST с Origin не заменяет браузерную проверку CORS и отображения ответа.
2. Последовательный идентичный повтор проверен. Это не полноценный concurrent contention/load test native Firestore; высоконагруженная работа не заявляется.
3. Бюджетные уведомления и policy очистки сборочных образов ещё не настроены. Ресурсы Яндекса не удалены; перенос сам по себе не прекращает возможные расходы их хранения.
4. Научные и национальные performance/validation gates этой проверкой не закрываются. Персонажи и их диалог остаются демонстрацией, а не результатом валидации модели.

## Перед продолжением

Подтвердить публикацию runtime config и закончить браузерный Pages→API путь;
не считать обновление исходников доказательством успешного Pages rollout.
Перед дальнейшими облачными изменениями сверить effective IAM и реальную ревизию.
Не повторять создание существующих проекта, базы или секретных версий. Создавать
только ресурсы этой демонстрации; не менять другие Google Cloud проекты и не
удалять Яндекс без отдельного решения владельца.

Секреты передаются только серверному хранилищу; не использовать аргументы
shell-команд, файлы исходников или screenshots. Firebase CLI `login:list --json`
может включать токены: не выводить сырой результат. Путь добавления версии
секрета в CLI может логировать request body, поэтому он не используется.
Операторский `createPrivateSecretsOperator` из
`deploy/firebase/scripts/private-secrets.mjs` работает только с указанными
проектом/двумя именами, не читает значения секретов и не входит в Functions
package. Перед будущей разрешённой записью необходим долговечный несекретный
marker и единственный оператор; неизвестный исход не повторяется автоматически.
При существующих версиях helper отказывается добавлять новые. Ограничения и API
использования: [README Firebase](../deploy/firebase/README_RU.md).
Не сохранять диалоги в Firestore.

Квоты запросов и число экземпляров ограничивают нагрузку, но не являются абсолютным ограничителем облачного счёта. Хранение, сборка и служебные ресурсы могут тарифицироваться отдельно. Готовность публикуется только после реального end-to-end прохождения.
