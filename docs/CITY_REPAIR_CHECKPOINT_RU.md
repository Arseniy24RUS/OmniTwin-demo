# Исправление города и дальние «огоньки» — 08.09.2026

## Граница результата

Это инженерная доработка **OmniTwin-demo**, не изменение научной модели. Официальная статистика не менялась. Полный синтетический город подготовлен локально, но **не включён в публичную версию**. Ниже не заявляется завершение всех пунктов городского плана или достижение универсального 30 FPS.

## Реализовано

- Один владелец состояния материалов; обычное вращение не выключает фасады. Текстурированный и упрощённый основные проходы зданий взаимоисключаются.
- Физические силуэты людей около 1,8 м, автомобили около 4,5 м с положительным отступом 0,1 м; поправка координатных единиц renderer, общий depth-correct canvas.
- Дальние люди — мягкие бирюзовые огоньки. При экранной высоте тела 3–5 CSS px свечение плавно заменяется обычным физическим силуэтом. Полный огонёк занимает 8 px по квадрату / около 5 видимых px. Это тот же ID и тот же retained instanced-слой, без bloom/FBO и отдельного canvas.
- Native GPU click сохраняет профиль жителя; скрытый зданием кандидат не становится доступным сквозь стену. Ближнее выделение — отдельный контур, не увеличение тела.
- Ленивый V2 provider, проверяемые сжатые чанки, согласованные сценарии, назначения и пагинация; происхождение и ограничения описаны в `CITY_V2_DATA_RU.md`.
- Подготовлены совместимый канонический server resolver и проверяемый uploader. Секреты и настройки OpenRouter не менялись; облачная активация V2 не выполнялась.

## Проверки и воспроизводимость

Команды из корня демо:

```text
npm test
npm run build
node tools/check-public-build.mjs
node node_modules/@playwright/test/cli.js test city-repair.spec.ts --project=desktop-1920x1080 --project=portrait-390x844
```

Playwright: один headed Chromium worker, настоящие приложение/API/тайлы, без `page.route`, подмены canvas или API. Включены native click по дальнему человеку, переход к тому же жителю вблизи, wheel zoom, удержание правой кнопки и вращение, кадры до/во время/после, запуск и остановка движения. Viewport/fullpage PNG, состояние, сетевой и console manifests сохраняются вне репозитория.

Ранняя серия `omnitwin-firefly-accepted-20260908`: четыре функциональных теста прошли, но мобильный ближний PNG **отклонён**, потому что карточка закрывала персонажа. Последующий production-прогон подтвердил повторное раскрытие панели при refresh выбранного жителя. Исправление: `onSelect` вызывается только жестом пользователя, внутреннее обновление выбранной сущности не раскрывает панель. Прежний paused-check читал счётчик с обновлением раз в секунду; теперь используются свежий render revision и нативные tile-loaded/idle признаки без ослабления лимита кадров.

Итоговая серия `omnitwin-firefly-release-20260908` на production preview: **4/4 Playwright, 38,5 с; все 32 viewport/fullpage PNG физически открыты и приняты для checkpoint 1**. Проверены дальний огонёк, настоящий GPU-клик, профиль того же жителя, переход к нему без свечения, доступность карты после сворачивания мобильной карточки, материалы до/во время/после вращения и движение. Для desktop и portrait после нативной стабилизации записано **0 новых кадров за 2200 мс**. Это локальная визуальная приёмка, не подтверждение обновления публичного сайта и не performance baseline. Из финальных desktop PNG собран и открыт contact sheet дальнего и ближнего вида.

Frontend: **259/259 тестов в 41 файле**, TypeScript без ошибок. Общие контракты/компиляторы/границы/publisher/public-shell: **50/50**. Production build проходит; публичный пакет 118 файлов, **37 358 093 bytes**, без больших `city-v2`/`demo-v2` файлов и распознанных встроенных ключей. Серверные проверки: 68/68; Firebase-адаптер: 20/20. Тесты полного локального V2 набора явно пропускаются в чистом CI без этих артефактов — пропуск не является data release gate.

Все FPS/временные измерения в этой кампании — `contaminated_diagnostic`: национальный расчёт не останавливался, фоновая нагрузка не контролировалась. Не заявляется чистый benchmark.

## Что не готово к выпуску

1. Проверить checkpoint 1 после публикации на настоящем GitHub Pages; локальная production mobile QA закрыта.
2. Полный V2 город: улучшить распределение дальних потоков по viewport, проверить видимую плотность улиц, реальные clicks/пагинацию крупного дома и ТЦ во всех нужных сценариях. Счётчик instances не заменяет видимость.
3. Выложить verified immutable assets в отдельный Firebase-проект, развернуть совместимый backend, проверить канонические V2 профили и только затем атомарно активировать набор. По умолчанию пока legacy.
4. Проверить release performance при контролируемой фоновой нагрузке; не подменять это кратким функциональным прогоном.

Научные исходники/расчёты и ранее подготовленные посторонние изменения Yandex не затрагивались. Superseded **сгенерированные демо-артефакты**, не исходники пользователя, перемещены в восстанавливаемые временные архивы; текущие manifest hashes и чанки сохранены.
